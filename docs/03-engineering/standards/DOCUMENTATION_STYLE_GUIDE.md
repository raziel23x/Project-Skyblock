# Documentation Style Guide

## Accessibility First

Project Skyblock documentation is written for fast scanning and reduced reading strain.

## Required Rules

1. Use one idea per section.
2. Keep paragraphs short.
3. Prefer direct sentences.
4. Use predictable heading order.
5. Explain abbreviations on first use.
6. Use diagrams for flows and dependencies.
7. Do not rely on color alone.
8. Put the most important information first.
9. Use the same term for the same concept everywhere.
10. Link to the canonical definition instead of repeating it.

## Standard Feature Order

1. Purpose
2. Player Experience
3. Requirements
4. Data Model
5. Extension Points
6. Compatibility
7. Failure Conditions
8. Testing
9. Acceptance Criteria

## Status Labels

Use one status:

- Proposed
- Draft
- Approved
- Implemented
- Deprecated
- Superseded
