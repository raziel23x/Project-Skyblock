# Project Skyblock Branding Guidelines

## Official Name

```text
Project Skyblock
```

Use the complete name in headings, release titles, project pages, and formal descriptions.

## Official Tagline

```text
Progress. Automate. Survive.
```

Preserve capitalization and punctuation.

## Primary Description

```text
A standalone Skyblock progression and automation mod for Minecraft 1.21.1 on NeoForge.
```

## Project Positioning

Project Skyblock expands gameplay after a Skyblock world has already been created.

Do not describe it as:

- A Skyblock world generator
- An ore-generation mod
- A required addon for another content mod
- A complete item or fluid pipe mod

Describe it as:

- A standalone Skyblock progression mod
- A renewable resource-generation mod
- An automation and machine mod
- A configurable NeoForge mod
- A mod with optional integrations

## Official Technical Terms

Use these names consistently:

- Material Crusher
- Thermal Generator Mk I
- Basic Energy Cable
- Structural Energy Frame
- Cobblestone Generator
- Water Generator
- Lava Generator
- Repair Gem
- Mixing Bowl
- Red Reagent
- Green Reagent
- Blue Reagent

Do not shorten or rename these terms in public documentation unless the in-game name also changes.

## Supported Platform

```text
Minecraft 1.21.1
NeoForge
Java 21
```

Update every public-facing document together when supported versions change.

## Project Icon

Current icon filename:

```text
project-skyblock-curseforge-icon.png
```

Do not rename or replace the icon without checking:

- CurseForge project icon requirements
- GitHub README references
- Release artwork
- Existing promotional links

## Public Documentation Locations

The following files must remain synchronized:

```text
README.md

branding/release-description-template.md
branding/screenshot-plan.md
CHANGELOG.md
TODO.md

```

## Feature Documentation Rule

A player-visible feature is not considered fully documented until the relevant public-facing material has been reviewed.

Check:

- README feature list
- CurseForge description
- Screenshots
- Release notes
- Changelog
- Configuration documentation
- Compatibility notes
- Issue-report instructions

## Writing Style

Use:

- Direct feature descriptions
- Clear headings
- Exact in-game names
- Short paragraphs
- Player-relevant explanations
- Pack-author configuration details where useful

Avoid:

- Unexplained internal class names
- Claims about unfinished features
- Marketing claims that cannot be demonstrated
- Legacy Forge terminology for the NeoForge version
- Vague phrases such as “many features” or “and much more”

## Image Standards

- Keep the project icon square.
- Preserve a readable silhouette at small sizes.
- Keep text readable when used in banners.
- Avoid screenshots of unfinished placeholders.
- Keep source artwork separate from exported public images when source files exist.

## Link Standards

Primary public destinations:

- CurseForge project page
- GitHub repository
- GitHub issue tracker
- Optional PayPal support link

Check links before each public release.

## Maintenance Rule

Whenever a visible feature, supported version, name, integration, or configuration changes, update all affected branding and public documentation in the same development pass.
